# (أ) متجر الثيمات

## 1) الفكرة

- كل ثيم له **نوع**: `landing` (صفحة منتج واحد — زي ملاك وسيليا وليالي) أو `store` (متجر كامل).
- الثيم إما **مجاني** للكل، أو **مدفوع** يتشرى **مرة واحدة ويفضل ملك التاجر للأبد**.
- الشراء محتاج صلاحية `buy_themes` في الباقة (برو / ماكس). ثيم المتجر محتاج كمان `store` عشان يتستخدم.

## 2) بيانات كل ثيم (يعدلها الأدمن)

| الحقل | ملاحظات |
|---|---|
| الاسم، الـ slug | |
| النوع | landing / store |
| وصف قصير | يظهر على الكارت |
| وصف كامل | يظهر في صفحة التفاصيل (نص منسق بسيط) |
| السعر | 0 = مجاني |
| الخصم | نسبة % + تاريخ بداية ونهاية اختياريين → يظهر السعر القديم مشطوب و«خصم 20%» |
| الصور | معرض: لقطات ديسكتوب وموبايل، صورة غلاف، ترتيب بالسحب |
| الهاشتاجات | ملابس، إكسسوارات، عطور، إلكترونيات، مستحضرات تجميل… (الأدمن يدير القائمة) |
| المعاينة | رابط معاينة حية ببيانات تجريبية (شرح تحت) |
| مميزات الثيم | نقاط (مثلًا «سلايدر في الهيدر»، «وضع ليلي») |
| أقل باقة مطلوبة | اختياري، مثلًا ثيم معين لماكس بس |
| مميز / جديد | للترتيب والظهور في «الأحدث» |
| ظاهر في المتجر | إخفاء بدون حذف |
| تاريخ الإصدار، رقم الإصدار، عدد المشتريات | عدد المشتريات بيتحسب أوتوماتيك |

**مهم:** الثيم نفسه **كود** (فولدر React في `front/src/themes/<key>` + سطر في الـ registry). الأدمن بيدير **بيانات العرض والسعر** بس لثيمات موجودة في الكود. مفيش رفع ثيم من الأدمن (ده أمان وجودة). ثيم جديد = أنا أبنيه ← يظهر في الأدمن «غير منشور» ← إنت تكمل بياناته وتنشره.

## 3) المعاينة الحية

- مسار عام `/theme-preview/{key}` (على الدومين الرئيسي للمنصة) بيرسم الثيم ببيانات تجريبية جاهزة (منتج / متجر تجريبي بصور مولدة، زي `/dev/themes` بس للإنتاج ومن غير أدوات المطور).
- تبديل موبايل / ديسكتوب، وتبديل بين 2–3 هويات ألوان عشان العميل يشوف الثيم بألوان مختلفة.
- الفورم والطلبات معطلين في المعاينة.
- البيانات التجريبية دي **محتوى عرض للثيم** مش بيانات وهمية في نظام التاجر (ما بتتخزنش في الـ DB ولا تظهر في أي داشبورد).

## 4) الجداول

- `themes` (موجود، يتوسع): `kind`، `slug`، `short_description`، `description`، `price`، `discount_percent`، `discount_starts_at`، `discount_ends_at`، `min_plan_key` null، `is_featured`، `is_listed`، `released_at`، `version`، `features` json.
- `theme_images`: `theme_key`، `media` (ملفات منصة مش tenant)، `kind` (cover | desktop | mobile)، `position`.
- `theme_tags` + `theme_tag` (ربط).
- `theme_purchases` (tenant): `theme_key`، `invoice_id`، `price_snapshot`، `source` (purchase | admin_grant)، `purchased_at`. unique(tenant_id, theme_key).
- قاعدتين منفصلتين:
  - `ThemeAccess::owns(tenant, theme)` = مجاني **أو** مشترى **أو** متدّي من الأدمن → يفتحه ويخصصه في الـ Builder.
  - `ThemeAccess::canPublish(tenant, theme)` = يمتلكه **و** (مجاني **أو** الباقة فيها `buy_themes`) **و** (لو store: الباقة فيها `store`) → يتعرض للزوار. بيتفحص في النشر وفي عرض الصفحة العامة.

## 5) الشاشات

**داشبورد التاجر ← الثيمات:**
1. **ثيماتي** (فوق): الثيمات المجانية + اللي اشتراها، متقسمة تبويبين «لاندنج» و«متجر»، وزرار «استخدم» على كل واحد.
2. **الأحدث المدفوعة** (تحت): شريط بآخر الثيمات المدفوعة + زرار «تصفح متجر الثيمات».
3. **متجر الثيمات**: شبكة كروت (غلاف، اسم، نوع، سعر قبل / بعد، شارة الخصم، الهاشتاجات، شارة «تمتلكه») + فلاتر: النوع، الهاشتاج، مجاني / مدفوع، السعر + بحث + ترتيب (الأحدث، الأكثر مبيعًا، السعر).
4. **صفحة الثيم**: معرض الصور، الوصف، المميزات، الهاشتاجات، السعر والخصم، زرار «معاينة حية»، وزرار الشراء:
   - مش في برو / ماكس → «رقّي باقتك عشان تشتري الثيم» (رابط للأسعار).
   - تمتلكه → «استخدم الثيم».
   - غير كده → «اشتري الآن» ← صفحة الدفع ([2-PAYMENTS.md](2-PAYMENTS.md)).
- في معالج إنشاء الصفحة وتبديل الثيم في الـ Builder: الثيمات اللي مش مملوكة تظهر بقفل + «شوف في المتجر».

**الأدمن ← الثيمات** (موجودة، تتوسع): كل البيانات اللي فوق، رفع الصور، إدارة الهاشتاجات، إهداء ثيم لـ tenant، إحصائيات المبيعات لكل ثيم.

## 6) خطوات التنفيذ (أ)

| # | الخطوة |
|---|---|
| T1 ✅ | توسيع `themes` + الصور + الهاشتاجات + `theme_purchases` + `ThemeAccess` وفرضه في الصفحات والـ Builder |
| T2 ✅ | API الكتالوج (`GET /dashboard/themes/store`، `GET /dashboard/themes/{key}`) + أدمن الكتالوج |
| T3 ✅ | شاشات «ثيماتي» و«متجر الثيمات» وصفحة التفاصيل |
| T4 ✅ | المعاينة الحية `/theme-preview/{key}` |
| T5 ✅ | الشراء عن طريق الفواتير والدفع + الإهداء من الأدمن |
| T6 ✅ | الثيمات الحالية: **ملاك مجاني**، **سيليا وليالي مدفوعين** (ثيمات لاندنج بس، مش هيتعمل منهم نسخ متجر) |

# (ب) المتجر الإلكتروني الكامل

## 7) الوضع الحالي (اللي هنبني عليه)

- موجود: منتجات بخيارات وفروق أسعار، صور، عروض، أكواد خصم، شحن بالمحافظات، هويات، دومينات، طلبات COD بـ `order_items`، بيكسل، تحليلات، Builder بأقسام.
- **ناقص للمتجر**: تصنيفات، slug لكل منتج، مخزون، سلة بأكتر من منتج، checkout، صفحة قائمة منتجات وبحث، قوائم تنقل، صفحات ثابتة، ثيمات متجر.
- **نقطة مهمة**: جدول `orders` حاليًا مبني على منتج واحد (`product_id`، `quantity`، `unit_price` على الطلب نفسه). المتجر محتاج الطلب يبقى **مجموع سطور** في `order_items`. ده تغيير حساس على الطلبات واللاندنج الحالية → خطوة لوحدها باختبارات كتير، وطلبات اللاندنج تفضل شغالة زي ما هي (سطر واحد).

## 8) شكل المتجر

- **المتجر هو أساس المنصة، واللاندنج ميزة جانبية.** ده بيأثر على الترتيب في القائمة الجانبية، وعلى الإعداد الأول بعد التسجيل، وعلى الرسائل التسويقية.
- **متجر واحد بس لكل tenant**، ومش هينفع أكتر. أما صفحات اللاندنج فينفع يعمل منها أكتر من واحدة (حسب حد الباقة)، وكل لاندنج ليها ثيم ومنتج خاصين بيها.
- الكل على نفس الدومين:
  - `/` الرئيسية بتاعة المتجر (مبنية بالـ Builder)
  - `/products` كل المنتجات + بحث وفلاتر · `/products/{slug}` صفحة المنتج
  - `/categories/{slug}` · `/cart` · `/checkout` · `/pages/{slug}` (من نحن، سياسة الاسترجاع…) · `/track` (موجود)
  - صفحات اللاندنج تفضل على `/{slug}` زي ما هي (والـ slugs دي تتضاف للمحجوزة).
- **لما المتجر يتفعّل، الرئيسية `/` تبقى المتجر على طول.** خاصية «الصفحة الرئيسية» في اللاندنج بتشتغل بس لو المتجر مقفول (أو مش في الباقة).
- المتجر يستخدم نفس الهوية (لوجو، ألوان، خطوط، بيكسل) ونفس المنتجات والعروض والأكواد والشحن. **مفيش نسخة تانية من البيانات.**

## 9) ميزات المتجر — النسخة الأولى (MVP)

**التصنيفات**
- شجرة بـ `parent_id`: رئيسي ← فرعي ← فرعي الفرعي … (لحد 5 مستويات كحد أمان في `config/landing.php`). ممنوع اللف (تصنيف يبقى أب لجده)، وده بيتفحص في الـ back.
- لكل تصنيف: اسم، slug، وصف، صورة، ترتيب بالسحب، ظاهر / مخفي، SEO.
- المنتج يبقى في أكتر من تصنيف. صفحة التصنيف بتعرض منتجاته ومنتجات الفروع اللي تحته، وفيها breadcrumb وقائمة الفروع.
- حذف تصنيف ليه فروع أو منتجات: الفروع تطلع لأبوه، والمنتجات تفضل (بتتفك من التصنيف بس).

**المنتج** (نفس المنتجات اللي بتستخدمها صفحات اللاندنج)
- `slug`، `short_description`، ظهور في المتجر (on/off)، منتج مميز.
- **SEO لكل منتج**: عنوان، وصف، صورة المشاركة (OG)، noindex. ولو فاضي، بيتاخد من اسم المنتج ووصفه وأول صورة.
- **الخيارات** (زي اللي موجود دلوقتي ونظام سلة): التاجر بيضيف مجموعة خيارات (لون، مقاس، خامة…) باختيار واحد، ويكتب قيمها، ويحدد هل هي إجبارية. ولكل قيمة **فرق سعر برقم ثابت، زيادة أو نقصان** (مثلًا XL +50، المقاس الصغير −20). **تعديل مطلوب**: الـ validation دلوقتي بيرفض الأرقام السالبة (`min:0` في `ProductRequest`)، فلازم يقبلها، بشرط إن سعر القطعة بعد الخيارات ما ينزلش عن صفر (والـ `PriceCalculator` يفرض ده).
- **المخزون: 3 أنواع، التاجر يختار واحد لكل منتج** (`stock_mode`):
  1. `unlimited`: كمية غير محدودة (ده الافتراضي، وهو سلوك اللاندنج الحالي).
  2. `product`: كمية واحدة للمنتج كله، أيًّا كانت الخيارات.
  3. `variant`: كمية لكل **تركيبة** (أحمر × M = 4، أحمر × L = 0…). الجدول بيتولد من الخيارات الإجبارية، ولكل تركيبة: كمية و SKU اختياري. لو قيمة خيار اتضافت أو اتشالت، التركيبات بتتحدث من غير ما الكميات الموجودة تضيع.
  - الخصم من المخزون بيحصل عند إنشاء الطلب (جوه transaction + `lockForUpdate`)، والكمية بترجع لو الطلب اتلغى أو اترفض أو اترجع. ولو الكمية خلصت أثناء الطلب، العميل بيشوف رسالة واضحة.
  - لما الكمية تخلص: «نفذت الكمية» على المنتج أو على التركيبة، وزرار الإضافة للسلة بيتقفل. تنبيه للتاجر لما الكمية تقل عن رقم يحدده.
  - نفس المخزون بيتحسب في طلبات اللاندنج كمان (منتج واحد، مخزون واحد).
- فلاتر: التصنيف، السعر، المتاح بس، الخيارات (لون / مقاس). ترتيب: الأحدث، الأقل سعر، الأعلى، الأكثر مبيعًا. بحث بالاسم.

**السلة والطلب**
- سلة في المتصفح (localStorage) + تسعير من السيرفر دايمًا (`PriceCalculator` يتوسع لعدة منتجات: العروض لكل منتج، كود الخصم على الإجمالي، الشحن بالمحافظة).
- Checkout صفحة واحدة: الاسم، الموبايل، المحافظة، العنوان، ملاحظات + الحقول المخصصة → دفع عند الاستلام.
- **بدون حسابات للزبائن في الأول** (السوق المصري بيطلب بالموبايل). تتبع الطلب الموجود يكفي. حسابات الزبائن مرحلة لاحقة.
- نفس الحماية الحالية: المحظورين، الطلبات المكررة، rate limit، البيكسل (AddToCart، InitiateCheckout، Purchase).
- السلات المتروكة: نفس فكرة الطلبات المتروكة الحالية بس للـ checkout.

**المحتوى والتنقل**
- قائمة الهيدر والفوتر (Menu builder: تصنيف / منتج / صفحة / رابط) بالسحب.
- صفحات ثابتة بمحرر نص بسيط + قوالب جاهزة للسياسات.
- الرئيسية بالـ Builder بأقسام متجر: سلايدر بانرات، شبكة تصنيفات، شبكة منتجات (مميزة / الأحدث / تصنيف معين)، بانر عرض، آراء، مميزات (شحن سريع، دفع عند الاستلام)، عداد، إنستجرام/روابط، نشرة… + الأقسام الحالية اللي تنفع.

**SEO والأداء**
- sitemap.xml للمتجر، JSON-LD للمنتجات (Product، Offer، Breadcrumb)، canonical، صور responsive، ISR مع revalidate بالـ tags زي الحالي.

**الداشبورد**
- مجموعة «المتجر الإلكتروني»: تفعيل المتجر والإعدادات · التصنيفات · القوائم · الصفحات · تخصيص الرئيسية (Builder) · اختيار ثيم المتجر.
- الطلبات: نفس الشاشة، بس الطلب بقى يعرض كذا منتج + مصدره (متجر / لاندنج اسمها كذا).

## 10) ثيمات المتجر

- ثيم المتجر = **قوالب صفحات** مش أقسام بس: Header، Footer، كارت منتج، صفحة منتج، صفحة تصنيف / قائمة، السلة، الـ Checkout، + أقسام الرئيسية.
- نفس فلسفة الثيمات الحالية: نفس الـ schemas والـ props في كل ثيمات المتجر، والفرق في الشكل → التاجر يبدّل الثيم من غير ما يخسر حاجة. اختبار تكافؤ (parity) زي الحالي.
- الألوان والخطوط من الهوية (CSS variables)، RTL logical classes، Server Components.
- البداية: **ثيم متجر مجاني واحد بس** اسمه **«رواق»** (`rewaq`): نظيف وسريع، ونجرب عليه كل حاجة. وبعدين نبني الثيمات المدفوعة واحد واحد، وكل واحد بيتعمل في خطوة لوحده. الأسماء المقترحة ليهم بالترتيب: **«ديوان»** (`diwan`، فخم للعطور والإكسسوارات)، **«مدى»** (`mada`، عصري جريء للملابس والأحذية)، **«سوق»** (`souq`، كثيف للإلكترونيات والمنتجات الكتير).

## 11) الجداول (ب)

- `stores` (tenant، صف واحد): `is_enabled`، `theme_key`، `home_content` json (draft/published + version زي الصفحات)، `settings` json (عملة العرض، رسالة الهيدر، واتساب عائم، المنتجات لكل صفحة…).
- `categories` (tenant): `parent_id` null (self FK)، `depth`، `name`، `slug` (unique لكل tenant)، `description`، `media_id`، `position`، `is_visible`، `seo` json. + `category_product`.
- `products` (+ أعمدة): `slug`، `short_description`، `in_store`، `is_featured`، `stock_mode` (unlimited | product | variant)، `stock` null (للنوع product)، `low_stock_threshold` null، `seo` json.
- `product_option_values.price_delta`: يقبل السالب.
- `product_variants` (للنوع variant): `combination_key` (أرقام القيم مترتبة، unique لكل منتج)، `sku` null، `stock`. (السعر بيتحسب دايمًا من فروق الخيارات، مفيش سعر خاص للتركيبة في الأول.)
- `stock_movements` (tenant): `product_id`، `variant_id` null، `change` (+/−)، `reason` (order | cancel | manual)، `order_id` null: سجل يوضح الكمية اتغيرت ليه.
- `menus` + `menu_items` (tenant): `location` (header | footer)، `type`، `target_id`/`url`، `label`، `parent_id`، `position`.
- `store_pages` (tenant): `title`، `slug`، `body` (نص منسق معقّم)، `is_published`.
- `orders` (+ أعمدة): `source` (landing | store)، و`product_id`/`quantity`/`unit_price` يبقوا nullable والحقيقة في `order_items`.
- كلهم `BelongsToTenant` و `TenantExists` / `TenantUnique`.

## 13) قرارات اتاخدت (2026-11-10)
